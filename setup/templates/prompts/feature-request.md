# Feature Request Prompt Template

> Copy this prompt and fill in the brackets when asking Claude to implement a new feature.
> The more context you provide, the less back-and-forth is needed.
> For domain-specific feature workflows, use the service-specific skill generated by `/customize-service-setup` (e.g. `/add-device`).

---

## Prompt

Implement the following feature:

**Feature:** [Name of the feature in 1–2 words]

**Goal:** [One sentence: what problem does this solve for the user?]

**Acceptance criteria:**
- [ ] [Specific, testable condition 1]
- [ ] [Specific, testable condition 2]
- [ ] [Edge case that must be handled]

**Scope:**
- Touches: [files, layers, or services expected to change]
- Does NOT touch: [things that are out of scope]

**Constraints:**
- [Technology constraint: e.g. "must use existing RabbitMQ client"]

**Reference:**
- Similar existing implementation to follow: [file path or feature name]
- Ticket / issue: [link or number]
